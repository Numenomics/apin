Benchmark

The benchmark has five tasks. Each gives a coding agent a working sampler and asks for a faster one. Every model starts from the same code in the same sealed container, may work for up to 24 hours, and is graded on hidden seeds.

Speed-up is the geometric mean, over the five tasks, of the sampler's efficiency relative to the starting code. Each block is one task. Scoring

  • The verifier runs the agent's file on hidden seeds and divides its efficiency by the efficiency of the starting code. That ratio is the speed-up.
  • A model's score is the geometric mean of its speed-ups over the five tasks. A result that fails the validity checks counts as 0.1×, so a broken sampler costs more than an unchanged one.
  • Efficiency is accuracy per unit of cost. It is a soft minimum over six classes of target shape, so a gain on easy Gaussians cannot offset a loss on funnels.
  • A difference under 5% is noise. When copies of one sampler that differ only in their random draws were scored at eight repeats, none came out more than 3% above the original.
  • Each task row also shows a Stan-style reference. It is Stan's NUTS with step-size and diagonal mass-matrix adaptation, rewritten for this harness and checked against CmdStan. The judge measures short runs from scattered starting points and charges double for gradients, which does not suit NUTS, so the reference scores between 0.7 and 1.3 times the starting code.
  • When a result fails only statistical checks, the verifier scores it on a second seed and marks it invalid only if it fails again. About 2 valid results in 100 are still marked invalid.
  • A run that the model provider or the infrastructure cuts off is not scored. It never counts as a zero or as a result.
  • The container holds the harness, the lane documents and the starting code. It holds no other sampler, and during a run it can reach only the model provider.
