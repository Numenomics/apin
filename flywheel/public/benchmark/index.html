Agent benchmark

The benchmark has eight tasks from real sampler work: three bugs to fix and five samplers to speed up. Every model uses the same starting code in the same sealed container and may work for up to 24 hours. The verifier grades the result on hidden seeds.

How a run is scored

  • Fix tasks are pass or fail. The agent gets a sampler with a real bug; the task is solved if the repaired code passes a hidden invariance or Jacobian check.
  • Speed-up tasks use a Stan-style reference. The verifier scores the agent's file on hidden seeds and divides its efficiency by the reference's. The reference is Stan's NUTS with step-size and diagonal mass-matrix adaptation, rewritten for this harness and checked against CmdStan. In the two lanes where the judge fixes the kernel, the reference is Stan's warmup alone.
  • The reference is not a high bar. The judge measures short runs from scattered starting points and charges double for gradients, which does not suit NUTS. On these tasks the reference scores between 0.7 and 1.3 times the starting code. Each task row above shows that ratio and the lane's frontier (its best sampler), where one passes the hidden checks.
  • A solved speed-up result meets three conditions. It must pass every validity check, beat the starting code by at least 5% and be at least as efficient as the reference, so returning the starting code unchanged does not count. The 5% margin comes from scoring copies of one sampler that differ only in their random draws: at eight repeats none scored more than 3% above the original.
  • A chance rejection gets a second look. The statistical checks reject about one valid sampler in eight by chance at eight repeats. When a result fails only such a check, the verifier scores it again on a second seed and calls it invalid only if it fails again. That leaves about 2 valid results in 100 marked invalid.
  • The weakest shape sets the efficiency. Efficiency is a soft minimum over target classes (a power mean with exponent −4), so a gain on easy Gaussians cannot offset a loss on funnels.
  • Cut-off runs are not scored. If the model provider or the infrastructure ends a run, the page draws it hatched and leaves it out of every count, whatever it produced; it never counts as a zero or a pass.
  • The container is sealed. It holds only the harness, the lane documents and the starting code, and during a run it can reach only the model provider.
