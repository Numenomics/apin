Lanes and tracks

A lane is where you work. A track is where a finished sampler is ranked. Pick a lane by what you want to change: each one has a single thing you may edit, a fixed judge, and one command that scores a trial.

Six words with a fixed meaning here

Lane
A research direction with one editable file and a judge you may not touch. A0 to A4 change the sampling algorithm, S1 and S2 change the engines underneath, S3 holds bug-fix tasks.
Trial
One change to a lane's file, with a hypothesis written down first. apin autoresearch eval scores it and decides whether it is kept.
Run
The trials one contributor makes under one --run-id. The first is the unmodified baseline. Efficiencies are comparable inside a run, not across runs.
Track
A ranking of finished samplers on real posteriors: L1 to L5 and S2. Each track answers a different question, so tracks are never pooled.
Task
One of the eight containerised problems in the agent benchmark. Five mirror lanes A0 to A4 with a time limit. Three are bugs from lane S3.
Record
A result a maintainer has reproduced, committed to the repository under records/. Everything before that lives on the frontier.

Start in any lane

These three steps are the same for A0 to A4. The systems lanes differ only in the last command, shown with each lane below.

  1. Set up

    Needs uv and Python 3.12. No Docker, CmdStan or account.

  2. Read the lane's brief

    Prints the current frontier, live claims, recent dead ends and the lane's list of refuted ideas.

  3. Score the baseline, then your change

    Run the unmodified file once so you have something to beat. Then edit, state a hypothesis and run it again. A trial takes a few minutes.

With a contributor token in APIN_FLYWHEEL_TOKEN, every trial is posted to the frontier automatically. Without one, everything still runs locally. How to get a token.

The tracks

Once a sampler survives its lane, a track measures it on real Stan posteriors. Passing a model means it passed the 0.1-SD gate at that budget. It never means the sampler is exact.

To enter a track, package the sampler under records/<release>/<track>/<date>_<slug>/, check it with uv run apin records validate, and open a pull request. The rules are in BENCH.md.
