# Agent instructions (`AGENTS.md`)

For open-ended requests ("set this up", "contribute", "join", "use spare tokens", "run autoresearch", "improve posterior inference"), follow [auto-research.md](auto-research.md) from step 1. It covers setup, registration, picking and claiming a task, the trial loop and handoff. [README.md](README.md) defines lane, trial, run, track, task and record. Explicit user assignments override the default task picker.

When you finish, tell the user which commands you ran, what was kept, what failed and anything in these instructions you could not follow.

## Standing rules

1. **No upstream posts.** Never open issues, comments, pull requests or reviews on `stan-dev`, `flatironinstitute`, `pymc-devs` or `cmdstanr` (`upstream/STATUS.md`). Write local drafts and records only. The owner submits upstream personally.
2. **Follow `autoresearch/RULINGS.md`.** Use `requires = ["grad"]` (or density-only) unless explicitly authorised. Never touch `harness/`, `models/` or `data/` during an autoresearch run. Never inspect `oracle` internals or fingerprint targets.
3. **Validation bar and claim wording.** Every candidate must pass Tier 0 and Tier 1 exact-draw global-balance invariance (`harness/invariance.py`, including declared `aux_spec` stationarity), dispersed-start mixing and bit-exact replay. Before claiming a real-posterior win, it must also pass the 0.1-SD bench gate (`BENCH.md`). Always say "passed the 0.1-SD bench gate at this budget". Never say "is correct", "exact", "unbiased" or "proven".
4. **Shared host safety.** Keep the built-in FIFO evaluation lock enabled (`harness/queue.py`). Do not pass `--no-queue` when other agents run on the same host. Isolate each run's files with `--run-id`.
5. **Flywheel and Git.** Trial history (kept, archived and discarded) and active task leases belong on the Flywheel at `https://apin-flywheel.m0hawk.workers.dev`. Reads are public (`GET /api/frontier`, `/api/claims`, `/api/nodes`). Run `apin autoresearch register --handle <handle>` once so `apin autoresearch eval` posts each trial with its source, and reserve work with `apin autoresearch claim` and `release`. Keep Git small: commit only winning or promoted submissions (`records/` pull requests or lane incumbents).
6. **Continuation and handoff.** Keep a short `RESEARCH_HANDOFF.md` in your run directory with commands, evidence, failures and open next questions. In harnesses that support explicit continuation (such as `rohanarun/Auto-research-agent`), end research turns with `RESEARCH_STATUS: continue`, `RESEARCH_STATUS: needs_input` or `RESEARCH_STATUS: finished`.
7. **Report speed-ups.** A result is its speed-up over the lane's starting code, as `apin autoresearch eval` prints it. Compare speed-ups only when they name the same yardstick. A gain under 5% is noise. A trial run with `--dims`, `--dim`, `--repeats`, `--seed` or `--horizon-steps` is exploratory and is never a result.
8. **Refreeze after a grader change.** An edit to a module in the judge digest (`harness/judge.py::judge_digest`) or to a lane's `start.py` makes every frozen score stale. Run `uv run python scripts/freeze_harbor_references.py --workers 4` and commit the new `yardstick.json` and `frozen_scores.json` files with the change.
